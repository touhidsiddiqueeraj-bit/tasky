Tasky — WebRTC ICE diagnostics

This page gathers ICE candidates from your network using the same STUN servers that Tasky uses. Run it on each device / network you want to test calls between.

What to look for:
• host candidates = your local IP (only useful on same LAN)
• srflx candidates = STUN-discovered public IP (needed for cross-network P2P)
• relay candidates = TURN relay (none — pure P2P)

If you see srflx candidates on both peers, cross-network P2P should work. If you only see host candidates, STUN is blocked on your network (firewall, captive portal, strict NAT) — that's why calls fail across networks.

How to interpret

Calls between two peers on the same LAN only need host candidates.
Calls across different networks need at least one srflx candidate on each side, AND the NAT on both sides must allow inbound UDP on the discovered port (this is true for "full-cone" NAT, but NOT for "symmetric NAT").
If either peer is behind symmetric NAT, pure P2P without TURN will not work — this is a fundamental WebRTC limitation, not a bug in Tasky.
